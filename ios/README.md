# 音浪 iOS / iPadOS

原生 SwiftUI 通用应用，最低 iOS / iPadOS 17。iPhone 与 iPad 使用同一套安卓页面结构，iPad 仅扩展可用宽度、封面网格列数并支持横竖屏，不增加侧栏。首页默认经典影像，直接复用安卓版 `home_music_light/dark`、`home_books_light/dark` 原图。

## 0.8.17 修复菜单收起后的拖动衔接

构建号 20。针对实机反馈的“长按 3 秒后不能拖动”，移除依赖 `UILongPressGestureRecognizer` 在系统菜单收起后仍为 `.began/.changed` 的门槛。改用从触摸开始即工作的非独占触摸观察器，独立保存按下、移动和松手状态，允许系统菜单与普通滚动同时识别；3 秒计时器加入 run loop 的 common 模式，在系统菜单跟踪触摸期间仍可计时。

持续按住且未移动时，3 秒收起菜单；菜单关闭后只检查原手指是否仍按着，再接续原尺寸拖动，不再读取旧长按识别器的状态。普通滑动／移动到菜单操作会取消排序计时，提前松手或系统中断不留拖动浮层。排序期间暂时锁定原页面手动滚动，仍支持程序化边缘滚动，松手或中断恢复滚动；保留触感提示、卡片二维换位与松手后防误打开。

本版未做真机验收。沿用用户要求：不运行测试，启动 iPhone／iPad 通用设备 Release 编译后结束，不等待构建完成、不发布下载链接。

## 0.8.16 歌单系统长按菜单（历史版本，实机发现拖动衔接问题）

构建号 19。移除音乐库歌单卡片与列表行的三点编辑按钮。自己的歌单改用 UIKit 原生 `UIContextMenuInteraction`，长按弹出“编辑歌单／更换歌单封面／删除歌单”；松手可保留菜单选择操作，删除需再次确认并校验当前服务器账号与歌单修改权限。VoiceOver 提供相同编辑、封面和删除操作。

同一次触摸持续按住满 3 秒时，通过公开 `dismissMenu()` API 收起菜单，在菜单收起动画结束且手指仍按住时接续原尺寸拖动；提前松手或取消不开始排序。拖动与菜单期间禁止普通点击打开，松手后继续短暂抑制进入歌单。卡片与列表均保留原尺寸、二维／上下换位、边缘自动滚动和本账号排序保存。菜单手势与三秒按住识别允许同时存在，普通滚动不进入排序；共享歌单继续只读。

系统菜单与生命周期接口根据 [Apple UIContextMenuInteraction](https://developer.apple.com/documentation/uikit/uicontextmenuinteraction) 和 [dismissMenu()](https://developer.apple.com/documentation/uikit/uicontextmenuinteraction/dismissmenu()) 核对；三秒衔接是应用对系统菜单的定制时序。本轮按用户要求不运行测试、未做真机手势验收；启动 iPhone／iPad 通用设备 Release 编译后结束，不等待构建完成，也不发布下载链接。

## 0.8.7 歌单、封面缓存与刷新

构建号 10。Navidrome 按安卓提供“我的歌单／共享歌单／创建歌单”按钮，按 owner 区分自己的与他人共享的歌单，仅自己的歌单显示编辑入口并允许拖动。原排序按服务器账号保存，新歌单稳定追加；拖动保持原尺寸、实时换位和边缘滚动，原位置保留半透明行，取消拖动恢复原顺序。整行普通点击仍可进入，拖动期间及松手后短暂阻止打开，避免误进入。

歌单内“排列歌曲”提供原顺序、加入日期、歌曲名、艺术家、专辑、时长及升降序记忆。优先使用加入歌单时间，缺失时回退入库时间，未知日期排在最后；没有可用日期则隐藏日期选项。

在线歌单、榜单、音乐库和播放器封面使用共用内存及磁盘缓存，合并并发请求，跨页面和应用重启复用。Navidrome 图片键保留服务器、用户、封面 ID、尺寸，去掉变化的鉴权盐和 token；不同账号仍隔离。磁盘上限 128 MB、有效期 7 天，网络失败时回退已保存的图片。首页轮换封面及锁屏封面也使用该缓存。

预解析切歌复用准备任务和已验证地址，不再无条件显示“正在解析”；准备结果或实际播放失败后才重新解析。在线榜单／歌单详情刷新按钮提供 44 点点击区域、加载和完成状态，加载中再点会排队刷新；强制刷新绕过目录及 HTTP 缓存，并使用独立脚本环境更新可能缓存的榜单周期。

## 构建

GitHub Actions 的 **iOS universal unsigned build** 在 macOS 上生成设备 archive、未签名 IPA，并在 iPhone / iPad 模拟器上运行测试。构建产物 `YinLang-iOS-unsigned` 包含 IPA、SHA256 校验值、Xcode archive、测试结果和日志。未签名 IPA 需要自行签名后安装，无需将证书或 Apple ID 写入仓库。

macOS 本地构建：

```sh
# 在仓库根目录，先按根 README 准备 .reference/lxserver-2.2.0
npm ci
npm run catalog
node ios/scripts/prepare-resources.mjs
python3 ios/scripts/generate-project.py
xcodebuild -project ios/YinLang.xcodeproj -scheme YinLang \
  -configuration Release -destination 'generic/platform=iOS' \
  -archivePath ios/build/YinLang.xcarchive CODE_SIGNING_ALLOWED=NO archive
```

也可直接打开 `YinLang.xcodeproj`。源文件变动后重新运行项目生成脚本。生成的目录包、原图与官方听书源资源不重复提交；构建时从已有安卓/共享目录准备。

## 验收边界

iOS 使用系统 AirPlay。DLNA 转发支持当前在线文件和本机文件，HLS 不进行转码；自动发现需要签名时具有 Apple 的多播网络权限，未开通时可手动填写设备描述 XML 地址。`Multicast.entitlements` 提供相应配置参考，未签名构建不要求权限证书。音效通过本机音轨处理，HLS、受保护媒体和外部投送受系统输出路径限制。自动更新在进入前台时按周期执行，后台调度遵循 iOS 限制。音频格式取决于 iOS 解码能力。第三方音乐源、听书网站、登录验证码、Navidrome 实例及真实 AirPlay / DLNA 设备仍需使用实际账号与设备联调；模拟器编译和测试不能替代这些验收。
